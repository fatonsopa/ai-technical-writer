# Category save facts
An administrator submits a category change through the Websites page to the Database API. The API authorizes the caller and validates the category. A rejected request makes no writes. Accepted changes and history commit together; a successful response follows commit. Failure during that transaction rolls the request back. A lost response can occur after commit and leaves the client uncertain. There is no agreed automatic retry policy. Explain a proposed runtime sequence with these participants and failure alternatives. Use a meaningful overview, a participant key and numbered interactions. No queue, worker, extra service or hosting platform is involved.
