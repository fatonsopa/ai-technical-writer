# Approved product brief: Preview edition-source imports

This is a self-contained evaluation scenario, not a report about the Websites Review initiative. The target is an existing university AI-index application. Administrators import source mappings for one edition from a UTF-8 CSV. Today the import writes immediately, so mistakes are discovered after the data changes. Product wants a preview and an explicit confirmation. The following behavior is agreed; implementation has not begun.

Users: edition administrators upload and resolve mapping errors; analysts consume the published mappings but cannot import. Goal: detect mapping errors before writes and retain an attributable confirmed import. No historical error-rate baseline, adoption target, owner name, delivery date, or effort estimate has been agreed.

Scope: one edition per import, CSV headers university_code, source_url, label. No XLSX, background scheduling, cross-edition bulk import, automatic correction, undo feature, or production backfill. Preserve university_code as text, including 0042. Repeated exact rows are reported as duplicates. Malformed URLs, unknown university codes, duplicate edition/source mappings, and unauthorized editions block confirmation. Optional empty labels stay empty. No blank-row count or maximum-file limit has been settled.

IMP-01: Only an administrator authorized for the selected edition can preview or confirm. Direct calls must enforce permission. An analyst and an administrator of a different edition are denied without writes.
IMP-02: Preview parses the specified UTF-8 columns and returns row-level validation errors and duplicates. A preview never changes stored mappings.
IMP-03: A preview belongs to the requesting administrator and one edition. An explicit confirmation can use it for 15 minutes after creation; exactly at expiration it is invalid. Another administrator cannot confirm it. Confirmation rechecks authority and relevant mapping validity against current data.
IMP-04: Confirmation saves all accepted rows and an import-history record in one transaction, or neither. An intervening conflicting mapping makes confirmation fail without partial writes. Failed history insertion also rolls back the mappings.
IMP-05: Repeating confirmation of the same already-committed preview returns that import result without another mapping or history write. A lost response must not lead to a duplicate import.
IMP-06: Preserve exact university_code values and source URL text according to the agreed validation rules; 0042 must not become 42. No URL canonicalization rule has been approved.
IMP-07: The interface shows validation errors without enabling confirmation. On a confirmed failure it retains the preview for correction or a new preview as appropriate; it does not show success. A network timeout leaves outcome uncertain until a status lookup by preview ID resolves it.
IMP-08: History identifies edition, authenticated actor, preview ID, committed row count, and commit time. Failed or expired previews do not create successful-import history.

Design constraints supplied by the project team: React administration interface, PostgreSQL through existing Supabase functions, authenticated edition-role checks. Existing service file src/services/editionSources.ts handles writes; proposed UI src/pages/admin/editions/ImportSourcesDialog.tsx. These paths are supplied design context, not inspected files. New schema names and exact function signatures remain proposals. Additive storage must precede new callers; keep the old import route available until compatibility is reviewed, but it must not bypass the new accepted behavior once this release is enabled. There is no permission to execute application commands or query databases.

The team favors server-owned preview state and a transactional confirmation keyed by preview ID. Compare this with client-only preview validation if an architecture decision is needed. Detailed locking and expiration-clock implementation are unresolved design choices; explain their implications without silently choosing new product behavior. No performance threshold or maximum row/file size has been agreed. These missing resource limits are readiness decisions, not values to invent.

Testing resources: isolated database, edition A/B, administrator A/B, analyst, valid active mappings, exact-text code 0042, malformed URL, unknown code, repeated row, controlled clock, transaction/history failure injection, and interception that drops a successful commit response. No test has actually run for this feature. Setup/cleanup must stay isolated. A full specification should cover normal, denied, expired, conflicting, failed-history, repeated-confirmation, and lost-response branches, including both persisted state and interface feedback. Do not introduce website queues, categories, a 500-ID cap, or Websites Review performance limits.
